# Star Hub library recovery — 14 November 2026

The file library returned a generic server error because the application database principal could not access the folder and placement tables introduced in migration 014. On Server 2, the existing application principal received only the table privileges required by those operations. File listing then succeeded in the signed-in browser. The browser code was also updated so a successful list clears its own previous read error.

The newly visible tables originally used `ON DELETE CASCADE`. Star Hub's atomic-storage startup audit rejects cascading foreign keys; this prevented storage from initializing after a restart. The existing two constraints were changed to `RESTRICT` without deleting rows. File deletion now removes its own account-scoped placement in the same transaction. Future new tables use the corrected 014 migration, and 016 documents the explicit upgrade from the two original auto-generated constraint names. Account deletion, if implemented later, must explicitly remove dependent folders before removing the account.
